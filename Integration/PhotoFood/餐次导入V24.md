# 本机餐次导入 v1

客户端负责分配固定UUID餐次ID、实际进食时间与递增版本。LLM或食物分析App只填食物说明及热量估计范围，不应代替客户端编造时间、ID或确认操作。

```json
{
  "schemaVersion": 1,
  "meal": {
    "id": "B76DD6FA-80E9-4DC4-BA64-A00917881874",
    "revision": 1,
    "date": "2026-10-28T04:00:00Z",
    "title": "示例午餐（不是识别结果）",
    "kcal": 600,
    "lower": 450,
    "upper": 800,
    "notes": "需确认份量、油和酱料",
    "confirmed": false
  }
}
```

使用工程内ISO8601日期格式，按实际进食时间发送，不能发送未来餐次。热量范围必须满足0≤下限≤估计≤上限≤10000；这是输入约束，不是合理膳食标准。导入始终先清除确认标记，用户预览后确认；同ID只有更高revision可以替换旧记录。相同/较旧版本被拒绝，不重复累计。

App当前通过展开“导入饮食分析结果”粘贴JSON预览。它没有调用图像模型、上传照片或写入HealthKit。实际拍照分析需要另行连接用户选择的模型；现有食物App的HealthKit写入器约定仍保留。不要同时把同一餐的本机记录与健康摄入相加：能量收支页明确选择一个摄入来源。
