# Recovery Pocket：开源与算法审计

审计日期：2026-10-03。检查了 GitHub 仓库、文件清单、许可证文件及关键源码；版本记录见 repository-lock.json。以下为工程适配判断，未做独立生理准确性验证，已经适配 Whoordan 的三项恢复计算作独立对照，尚未替换正式评分。

## 结论

有可复用的底层库与 Swift 恢复估算代码；本次未找到可直接以 Apple Watch HealthKit 数据运行、且有独立验证的 Garmin Body Battery 等效开源实现。优先复用成熟计算与数据处理，不继续凭复杂度增加自创电量公式。开源许可、真实实现、数据匹配和验证证据必须分别检查。

## 当前实现必须解决的算法问题

1. **电量初值不对应同一时间。** HealthStore 使用前一有效夜的恢复分数，充当昨天零点电量；晨间恢复与午夜存量不是同一变量。跨日滑动窗口还会重新估计初值，可能造成不连续。正式使用前应建立有时间戳的持续状态与重算规则。
2. **充放电系数没有校准。** 每小时睡眠补充 6、低活动补充 1.8、每 35 kcal 消耗 1 等都是工程假设，未按个人、运动类型或样本验证。不能标为佳明等效。
3. **日内 HRV 尚未参与电量变化。** nightHRVZ 参数存在，但调用未传入，默认 0；HRV 只经恢复初值间接进入。当前没有连续 HRV 压力算法。
4. **小时中位心率不代表一小时连续观测。** 少量样本可触发整小时消耗；“6 条采样”也不证明覆盖整小时。下一版应保存覆盖时段，限制外推，区分训练内外采样。
5. **内部范围不是校准置信区间。** 目前按缺失、观测等规则调整范围，没有覆盖率实验；应继续明示为内部估算范围。
6. **卡尔曼只解决平滑问题。** V2 噪声、衰减和 0–100 映射仍是工程参数。31 项测试验证边界和计算行为，不能证明生理预测精度。

已经保留的合理保护：不把未知时段当作休息、避免多来源直接累加、睡眠区间去重、历史基线不包含未来、缺失停止评分、演示标签、摘要过期、清除后发送空摘要。这些也要在更换开源算法时保留。

## 推荐复用路线

先将 Whoordan 有许可证的恢复计算模块抽出为离线比较对象，保留许可证与修改记录，不复制其整个设备来源策略。用同一批带来源与采样覆盖的历史数据比较现有 V2、开源基线及简单个人基线；按时间留出验证，检查缺失、重算一致性、跨日跳变与用户自评的关系。

底层数值计算用 FilterPy 作参考验证；只有实际获得合格 RR/NN 序列，才使用 pyHRV/HeartPy。全天电量需要独立的连续状态与个体校准；本次候选不能替代这一层，不能把早晨 readiness 改名成全天电量。

设计参考以可解释分项、来源/覆盖、趋势与简短自评为主，使用本项目自己的 SwiftUI 布局和视觉资产。当前审核只阅读源码与测试，未运行第三方完整工程，也未找到候选整体准确性的独立验证结果。


## 本轮落实 · 2026-10-03

已加入 OpenRecoveryReference：适配 Whoordan RecoveryExplainer 的 HRV、心率和睡眠三项，保留原始权重与分项映射、按可用总权重归一化；增加有限/正值检查及完整三项门槛。来源与 Apache 2.0 许可见 ThirdParty/Whoordan。手机使用睡眠心率代替其静息心率，并在界面注明；因此不能将对照分数称为原项目完整输出。未增加呼吸、温度权限。对照有至少 14 个既往有效夜晚才显示，演示模式不虚构真实对照。

已移除晨间恢复分数作为午夜初值的调用，改为固定 50 的中性工程先验、较宽初始范围与带时间戳的小时聚合账本。重复刷新替换同一时段，重启读取账本，从同一初始状态重算。保留过去的聚合观测直到清除；未保存逐条心率样本到新增账本。此举解决刷新重新设起点的问题，不能证明固定初值正确，充放电率仍待校准。

新增心率覆盖代理：去重时间戳、超过 5 分钟的相邻间隔不记作覆盖、每段最多计一分钟；低活动补充要求至少半个时段覆盖，并仅作用于覆盖时长。该代理是保守处理，仍不是持续传感器采集时间，暂不用于宣称实时压力。

37 项合成行为检查通过，含重启/重复刷新、覆盖空洞、重复采样、开源映射基准与无效 HRV。真实数据准确性、时区变化、长期账本性能、个人系数校准和第三方完整算法一致性尚未验收。
